# PDF 转 Word 公网部署设计

## 目标

将现有 FastAPI PDF 转 Word 网页工具部署为可通过公网 HTTPS 地址访问的小工具。首个版本使用 Render 免费 Web Service，通过 GitHub 仓库自动构建和部署，并使用一个共享访问密码限制使用范围。

本次交付包括应用侧公网安全加固、容器化、Render 部署配置、GitHub 仓库准备和部署验证。转换目标仍是“优先可编辑”，支持文字型、扫描型及混合型 PDF。

## 范围与约束

- 使用 Render 免费 Web Service，不购买服务器或域名。
- 使用 Render 提供的 `onrender.com` HTTPS 地址。
- 应用密码只保存在 Render 环境变量 `APP_PASSWORD` 中，不写入源码、Git 历史或部署文件。
- 会话签名密钥只保存在 Render 环境变量 `SESSION_SECRET` 中。
- `说明.txt`、`.env`、运行时文件、上传文件、转换结果及本地虚拟环境必须从 Git 和 Docker 构建上下文排除。
- 不读取、打印或复用 `说明.txt` 中的 GitHub 密码。GitHub/Render 授权使用浏览器 OAuth、GitHub CLI 登录或个人访问令牌；若需要交互登录，由用户本人完成。
- 免费实例可能休眠，首次访问可能需要等待约一分钟；应用页面应提示这一限制。
- Render 文件系统是临时文件系统，所有任务状态和文件允许在重启或重新部署后丢失。

## 架构

浏览器通过 Render 托管的 HTTPS 地址访问 FastAPI 应用。未登录用户只能访问登录页、登录接口、静态资源和健康检查；登录成功后，服务写入带签名的安全会话 Cookie，用户才能访问首页和全部转换 API。

Render 根据 GitHub 仓库中的 `Dockerfile` 构建镜像。镜像安装 Python 依赖、Tesseract OCR 以及简体中文和英文语言包，随后使用 Uvicorn 单进程启动应用，监听 `0.0.0.0:$PORT`。单进程模型使内存任务状态、并发控制和内存限流的行为可预测。

任务文件继续写入 `.runtime/tasks`。上传后由线程池执行转换；下载完成或任务超时后清理文件。Render 重启会直接丢弃未完成任务，这属于免费版可接受限制，前端应给出可理解的重试提示。

## 认证与会话

新增独立认证模块，负责密码校验、会话状态和请求保护：

- `GET /login` 返回登录页；已登录用户跳转到 `/`。
- `POST /login` 使用表单提交密码，采用常量时间比较验证 `APP_PASSWORD`。
- 登录成功后仅在签名会话中保存布尔值 `authenticated=true`，不保存明文密码。
- `POST /logout` 清除会话并跳转至登录页。
- 会话 Cookie 设置 `HttpOnly`、`SameSite=Lax`；公网生产环境设置 `Secure`。
- `GET /health` 保持公开，只返回服务存活状态，不返回配置、任务或系统信息。
- `/`、`/api/convert`、`/api/tasks/{task_id}`、`/api/tasks/{task_id}/download` 全部要求认证。
- 未认证网页请求重定向至 `/login`；未认证 API 请求返回 HTTP 401 JSON，避免前端轮询误把登录页当作任务结果。
- 应用启动时若缺少 `APP_PASSWORD` 或 `SESSION_SECRET`，生产模式必须启动失败并给出不含敏感值的明确错误。本地开发模式允许使用显式开发配置，但 README 必须说明不可用于公网。

登录表单和转换提交使用同源校验：对修改状态的请求检查 `Origin` 或 `Referer` 是否与当前主机一致。会话 Cookie 的 `SameSite=Lax` 是第二层防护。登录失败仅显示统一提示，不泄露配置状态。

## 公网资源保护

免费实例资源有限，默认配置调整为：

- 最大上传文件：30 MB，通过 `MAX_FILE_SIZE_MB` 环境变量配置。
- 最大 PDF 页数：100 页，通过 `MAX_PDF_PAGES` 环境变量配置；在开始逐页处理前读取页数并拒绝超限文件。
- 同时执行转换：1 个线程。
- 总转换容量：2 个任务，即 1 个执行、1 个等待；超出时返回 HTTP 503。
- 按客户端 IP 做轻量内存限流：登录尝试每 10 分钟最多 10 次；转换提交每 10 分钟最多 5 次。超过限制返回 HTTP 429。
- 客户端 IP 默认取直连地址；只有请求确实经过 Render 代理时才读取平台提供的可信转发头，不盲目信任任意 `X-Forwarded-For`。
- 任务有效期维持 1 小时，下载完成即删除；定时清理过期任务。

限流数据只保存在进程内，服务重启后清零。共享密码版本不提供账号体系、密码找回、用户文件历史、持久数据库或计费功能。

## 页面行为

新增与现有视觉风格一致的中文登录页，包含密码输入、登录按钮和错误提示。首页增加简短说明：访问受密码保护；文件仅用于本次转换；免费服务休眠后首次打开可能较慢；支持不超过 30 MB、100 页的 PDF。

前端遇到 HTTP 401 时跳转到 `/login`；遇到 429、503、页数超限或文件过大时显示服务端中文错误。任务因实例重启而返回 404 时，提示用户重新上传，不表现为无限轮询。

## 部署文件

- `Dockerfile`：基于精简 Python 镜像，安装 Tesseract、`chi_sim`、`eng`、字体和项目依赖，使用非 root 用户运行。
- `.dockerignore`：排除 `.git`、`.venv`、缓存、测试缓存、`.runtime`、`.env`、`说明.txt` 和本地设计生成物。
- `render.yaml`：定义 Docker Web Service、免费实例类型、健康检查路径 `/health`，声明 `APP_PASSWORD` 和 `SESSION_SECRET` 为不落盘的环境变量。
- `.gitignore`：新增 `.env`、`说明.txt` 及常见密钥文件规则。
- `README.md`：补充本地密码配置、Docker 自测、GitHub 推送、Render 创建服务、环境变量设置、免费版限制及故障排查。

`render.yaml` 不包含任何真实秘密。若 Render Blueprint 无法自动生成安全随机值，用户在控制台手工填写；`SESSION_SECRET` 使用至少 32 字节的随机值。

## GitHub 与 Render 发布流程

1. 在本地先更新忽略规则，并确认 `说明.txt`、`.env`、`.runtime` 不在待提交文件中。
2. 初始化 Git 仓库，创建首个提交。
3. 通过用户本人已授权的 GitHub 登录创建私有仓库并推送；若免费部署对私有仓库授权受限，可在用户明确同意后改为公开仓库，但任何秘密仍不得进入历史。
4. 在 Render 使用 GitHub OAuth 连接仓库，按 `render.yaml` 创建 Web Service。
5. 在 Render 控制台设置 `APP_PASSWORD` 和 `SESSION_SECRET`，触发部署。
6. 验证公开地址的健康检查、未登录拦截、密码登录、PDF 上传、任务轮询、DOCX 下载及错误提示。

账号授权或验证码等交互步骤无法安全自动代替用户完成时，实施过程暂停在对应页面，由用户完成登录后继续。任何命令和日志都不得输出账号密码或令牌。

## 错误处理与可观测性

- `/health` 成功时返回 HTTP 200 和固定 JSON，例如 `{"status":"ok"}`。
- 启动配置错误直接终止启动，并仅指出缺失的环境变量名。
- 上传格式、大小、页数错误返回 HTTP 400；未登录返回 401；限流返回 429；容量耗尽返回 503。
- 转换内部异常继续向用户返回通用中文错误，详细异常只写服务日志且不得包含密码、Cookie 或文件内容。
- Render 部署验证同时检查构建日志、运行日志、监听端口和公网 HTTP 行为，不能只以“构建成功”作为上线完成依据。

## 测试与验收

自动化测试覆盖：

- 生产配置缺少秘密时拒绝启动，本地测试配置可安全注入。
- 登录成功、登录失败、退出、Cookie 属性和未认证拦截。
- 健康检查无需登录且不泄露配置。
- 同源校验拒绝跨站状态修改请求。
- 登录与转换接口按 IP 限流并返回 429。
- 30 MB 文件限制可由环境变量覆盖。
- 超过 100 页的 PDF 在转换前被拒绝。
- 单执行任务、单等待任务及第三个任务返回 503。
- Dockerfile、`.dockerignore`、`render.yaml` 不包含真实秘密，并具备正确启动命令和健康检查。
- 现有文字 PDF、扫描 PDF、混合内容和 DOCX 生成回归测试继续通过。

上线验收需要使用 Render 公网地址完成一次真实流程：未登录访问被拦截；正确密码可进入；测试 PDF 能转换并下载可打开的 DOCX；错误密码不可进入；下载后任务文件按策略删除。最终交付公网 HTTPS 地址、使用说明和已知免费版限制。

## 明确不做

- 不提供多用户注册、独立账号、找回密码或权限管理。
- 不提供永久文件存储、转换历史、数据库或对象存储。
- 不保证复杂 PDF 的像素级排版一致，也不新增商业 OCR 服务。
- 不购买域名、付费实例或第三方存储。
- 不把 GitHub、Render 或应用密码写入任何项目文件。

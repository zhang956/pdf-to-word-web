# PDF 转 Word 网页程序设计

## 目标

实现一个本地运行的网页程序。用户上传单个 PDF 后，系统自动处理文字型、扫描型和混合型页面，并生成以可编辑内容为优先的 DOCX 文件供下载。

首版不包含账号、数据库、批量转换、任务历史和云端 OCR。

## 技术架构

- 后端采用 Python 和 FastAPI，提供网页、文件上传、转换状态及 DOCX 下载能力。
- PDF 解析采用 PyMuPDF。每页先检测可用文本层；文字足够时直接提取，文字缺失或过少时调用 OCR。
- OCR 使用本机 Tesseract，默认识别简体中文和英文。
- DOCX 生成采用 python-docx，将内容写为可编辑段落和表格，并插入能够提取的原始图片。
- 前端采用原生 HTML、CSS 和 JavaScript，不引入前端构建工具。

## 转换流程

1. 用户拖拽或选择一个 PDF 文件。
2. 浏览器校验扩展名和文件大小后上传。
3. 服务端再次校验文件类型、大小和 PDF 格式，并创建独立临时工作目录。
4. 服务端逐页提取文本块、表格和图片，并根据文本密度决定是否执行 OCR。
5. 内容按页面及阅读顺序写入 DOCX。每个 PDF 页面在 Word 中对应一个分节或分页边界。
6. 页面展示转换进度；成功后提供 DOCX 下载，失败时展示可理解的错误信息。
7. 转换完成、下载结束或任务超时后清理临时文件。

## 内容处理规则

- 普通 PDF 优先使用原文本层，避免 OCR 引入错字。
- 扫描页使用 Tesseract 的 `chi_sim+eng` 语言组合。
- 段落按文本块的纵向和横向位置排序，合并明显属于同一段落的连续行。
- 可识别的表格转换成真正的 Word 表格；无法稳定识别为表格的内容按普通段落输出。
- 图片按其所在页面和大致阅读位置插入；装饰性小图可忽略。
- 复杂多栏、公式、手写文字、印章和特殊字体不承诺像素级还原，优先保证文字可编辑、顺序可读。

## 接口与页面

- `GET /`：转换页面。
- `POST /api/convert`：上传 PDF 并启动转换，返回任务标识。
- `GET /api/tasks/{task_id}`：返回任务状态、页数、当前页、进度及错误信息。
- `GET /api/tasks/{task_id}/download`：下载转换完成的 DOCX。

页面包含上传区、文件信息、开始转换按钮、进度条、状态提示、失败提示和下载按钮。转换期间禁止重复提交同一任务。

## 错误处理与安全

- 仅接受 `.pdf` 且内容可被 PDF 解析器打开的文件。
- 默认最大文件为 50 MB；超限时在前后端明确提示。
- 使用随机任务标识和独立临时目录，下载接口不接收任意文件路径。
- 对损坏、加密、无页面和转换失败的 PDF 返回明确错误。
- 单页失败时记录页码；不能可靠继续时终止任务，避免生成看似成功但内容缺失的文件。
- 临时文件不长期保存，应用重启时清理过期任务目录。

## 测试与验收

- 单元测试覆盖文件校验、页面 OCR 判定、文本排序、DOCX 生成和任务状态变化。
- 接口测试覆盖上传、状态查询、成功下载、错误格式、超大文件、损坏 PDF 和不存在的任务。
- 使用文字型 PDF、中文扫描 PDF、英文扫描 PDF、图文混合 PDF 和带表格 PDF 做端到端验证。
- 验收标准：普通 PDF 的主要文字可在 Word 中选择和修改；扫描 PDF 能生成可编辑文字；转换进度可见；成功文件可下载并由 Word 兼容软件打开；失败任务不会残留用户文件。

## 部署约束

- 运行环境需要 Python、Tesseract、简体中文和英文语言数据。
- 项目提供依赖清单、启动脚本和 README，说明安装及启动方法。
- 默认仅监听本机地址，避免未经配置就暴露到公网。
